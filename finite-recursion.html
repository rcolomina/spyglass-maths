The filter no recursion can build

The video ends with a claim: the filter made from Episode 1's numbers is perfectly stable, yet no finite recursion can implement it. This page explains what that means and why it is true.

What a finite recursion is

Most digital filters are computed by a recursion: each new output is a fixed combination of a few recent outputs and inputs.

y[n] = a1y[n−1] + … + aky[n−k] + b0x[n] + … + bmx[n−m]

"Finite" means the filter only remembers a fixed number of values, k past outputs and m past inputs. That is what makes it cheap: a few multiplications per sample, forever. The simplest example is a one-pole smoother, y[n] = p·y[n−1] + x[n].

Its fingerprint: geometric decay

Feed a filter a single click (1 at time 0, then zeros) and record the output. That is its impulse response, h[n]. For the one-pole smoother it is h[n] = pn: it shrinks by the same factor every step.

A recursion with more terms has more poles, and its response is a sum of such terms (possibly times polynomials in n). If the filter is stable, every pole satisfies |p| < 1, so the response is squeezed under a geometric curve: |h[n]| ≤ C·ρn for some ρ < 1.

On a logarithmic vertical axis, a geometric curve is a straight line. So every stable finite recursion lives on or under a straight line.

The Episode 1 filter

Now use Episode 1's terms as the impulse response:

h[n] = 1 / ((n+1)(n+2)) = 1/(n+1) − 1/(n+2)  →  ½, ⅙, 1/12, 1/20, …

By telescoping, these weights add up to exactly 1, so a bounded input always gives a bounded output: the filter is stable. But it fades like 1/n², a power law, not a geometric one. On the log scale its curve bends and keeps flattening.

Why it can never be matched

Push the slider towards 1 and the crossing moves further out, but it always comes. The reason is one line: divide our filter by any geometric curve.

h[n] / ρn = (1/ρ)n / ((n+1)(n+2))  →  ∞

The top grows exponentially, the bottom only like n², and an exponential always wins. So for every stable recursion there is a point after which the Episode 1 filter is larger than anything that recursion can produce. Adding more poles does not help: the response is still bounded by the slowest pole's straight line. No finite recursion, however large, can have this impulse response.

The same fact seen from the frequency side: a finite recursion always has a transfer function that is a ratio of two polynomials, while this filter's transfer function contains a logarithm, H(z) = (w + (1−w) log(1−w)) / w², with w = z−1. A logarithm cannot be written as a ratio of polynomials.

What this means in practice

A finite recursion forgets the past geometrically fast, because all it keeps is a fixed handful of numbers. The Episode 1 filter has a long memory: an input from long ago still matters, at 1/n² strength. Filters like this can only be approximated in a real system:

  • cut the response off after N taps and compute it directly (an FIR filter), costing N multiplications per sample, or
  • fit a recursion that tracks it over the range you care about, accepting that it will fall away eventually.

Either way, getting closer costs more. The exact filter is out of reach.
